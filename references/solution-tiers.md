# 选型访谈与方案档位（identity tiers）

> 执行本技能的第一步必读。访谈规则（三问 / 保守假设 / 理由要求）的**唯一权威**见
> agent-skills-index 的 `conventions/solution-interview.md`；本文只保留本技能的档位表（I0~I3）。

## 1. 访谈（一次问清，≤3 问）

| # | 问题 | 取值（示例） | 用途 |
| --- | --- | --- | --- |
| 1 | **目的** | 验证想法 / 自用经营 / 商业产品 / 多产品基础设施 | 档位主轴 |
| 2 | **规模** | 用户量级（<100 / <1 万 / <10 万 / ≥10 万）、产品数、团队 | 档位落点 |
| 3 | **硬约束** | 合规（等保/PIPL/GDPR）、技术栈、已有账号库要复用 | 修正取值 |

未回答的项按最保守假设处理并在产出标注"未确认"（规则见 `conventions/solution-interview.md`）。

## 2. 档位矩阵（目的 × 规模）

| 档位 | 目的 | 规模 | 典型方案 | 核心理由 |
| --- | --- | --- | --- | --- |
| **I0 内嵌最小** | 验证想法 | <100 用户，单产品 | password + 服务端会话 Cookie + 邮箱验证 | 最快拿到"有人注册登录"；不过度建设 |
| **I1 单产品完整** | 自用经营 / 商业起步 | <1 万用户，单产品 | I0 + 手机验证、封禁注销、限流审计、可选 TOTP | 陌生人开始进来，防爆破/枚举/盗号成为现实风险 |
| **I2 多产品共享身份** | 多产品复用同一账号 | 2+ 产品 | 共享账号库 或 OIDC SSO；RBAC 与权益分离 | 一个用户登录多个产品；身份只维护一份 |
| **I3 统一身份服务** | 多租户 / 高安全要求 | ≥10 万用户 或 合规强制 | 自建 identity 服务 或接 Keycloak/Auth0/Clerk | 会话规模、合规审计、企业 SSO 超出内嵌模块能力 |

**机器身份**（API key / mTLS / 私钥 / SSH）不属于 I0~I3 的任何一档——它是独立的 ServiceIdentity 模块（v0.2+）。
普通 SaaS 服务间调用先用 API key；SSH 是运维接入，归主机安全（server-hardening 技能）。

## 3. 换档触发器

**升档：**

- 用户量接近档位上限（80% 水位）；出现一次盗号/爆破/撞库事件 → 立即升档；
- 第二个产品要共用同一账号 → I0/I1 升 I2（至少把身份层独立）；
- 合规要求（等保、GDPR/PIPL 审计）→ 评估 I3；
- 团队多人维护且安全责任分散 → 升档并补齐审计告警。

**降档（避免过度建设）：**

- 目的只是验证想法 → 永不预建 MFA/OIDC/SSO；宁可 I0 跑通再升；
- 已建能力连续一月无真实使用 → 降级或退役（对齐 maintenance 纪律）。

## 4. 理由模板

```text
档位：I1
依据：目的=商业起步；规模=<1 万用户，单产品；硬约束=无等保要求
理由：陌生人开始付费，防爆破/枚举/盗号成为现实风险，需要限流审计与封禁注销
为什么不是 I0：已非验证阶段，安全短板不可接受
为什么不是 I2：目前只有一个产品，SSO/共享账号库无收益
未确认假设：（无）
```

## 5. 与会员技能（MSP）的关系

- 本技能的产物是 `principal`；MSP 消费 principal 做订单/权益/账本（见 MSP spec §1 身份边界）；
- 账户合并跨两个协议：身份域做 Identity 重绑，MSP 做段并集与账本 transfer（OP-M2）；
- 删除请求跨两个协议：身份域掩码 PII，MSP 负向条目清零余额（data-retention.md）。
