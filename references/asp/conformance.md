# ASP 符合性判定（Conformance）

> 把"认证系统是否可用"从主观判断变成可执行、可留证的检查。

## 1. 符合性等级

| 等级 | 覆盖 | 判定 |
| --- | --- | --- |
| **Core** | 注册/登录/会话/验证/密码重置/封禁注销/限流审计 | 必选，全部 MUST 通过 |
| **MFA** | TOTP + 备份码 | 在 Core 上追加 |
| **Federation** | OIDC 联合登录 | 在 Core 上追加 |
| **MultiProduct** | 多产品共享身份（SSO/OIDC 或统一账号库） | 在 Core 上追加 |
| **ServiceIdentity**（v0.2 预留） | API key / mTLS / 私钥登录 | 未定义，见 spec §9 |

实现必须显式声明支持哪些等级；只考核声明范围内的规则。

## 2. MUST 清单（全部可勾选）

**凭据与会话**

- [ ] A-1 身份与凭据分离：User 无登录标识；`(provider, provider_subject)` 唯一
- [ ] A-2 口令 Argon2id：库/日志/缓存无明文；哈希参数随串
- [ ] A-3 会话可撤销：token 随机、只存哈希；改密码/封禁/强制下线即撤销
- [ ] A-4 登录轮换会话标识（防固定）
- [ ] A-12 每次请求服务端校验会话（存在/未过期/未撤销/账号未禁用）

**防护与审计**

- [ ] A-5 防枚举：统一错误 + 恒定耗时 + 限速锁定；成败皆审计
- [ ] A-6 验证码一次性：绑定目的、短 TTL、限次、消费即失效
- [ ] A-7 密码重置经验证渠道，成功后撤销其它会话
- [ ] A-8 认证层只发 `principal`，不代判业务权限
- [ ] A-9 密钥独立管理、不进仓库
- [ ] A-10 审计完整：actor + reason + 时间 + 掩码 IP
- [ ] A-11 注销走掩码/匿名化，审计事实保留匿名引用

## 3. 设计判据清单（D-1~D-5，跨等级必检）

> 唯一权威定义（含认证域表述与通过证据）见 quality-gate-builder 的 design-judgments.md；
> 出处见 membership-system-builder 的 `master-craft.md` §3。本协议只保留判定要求，不复制定义。

- [ ] D-1 删表重建：sessions 可删可重建，用户与身份事实仍在
- [ ] D-2 一年后审计：禁用/改密可回溯到不可变审计记录
- [ ] D-3 并发同发：验证码并发消费恰一次成功
- [ ] D-4 事件重放：登录成功事件重放不重复发会话
- [ ] D-5 回滚演练：旧版本可读新版本会话/审计数据

## 4. 测试向量

| ID | 场景（等级） | 期望 |
| --- | --- | --- |
| S-01 | 注册成功（Core） | user+identity+credential 同事务；重复 `(provider, subject)` → `IDENTITY_TAKEN`，无部分写入 |
| S-02 | 防枚举（Core） | "用户不存在"与"密码错误"响应一致且耗时恒定 |
| S-03 | 登录成功（Core） | 新会话创建，服务端只存哈希；Set-Cookie HttpOnly/Secure/SameSite |
| S-04 | 失败限速锁定（Core） | 连续 5 次失败 → `RATE_LIMITED`；窗口内正确密码也被拒 |
| S-05 | 会话固定（Core） | 登录前后会话标识不同，旧标识立即失效 |
| S-06 | 改密码撤销其它会话（Core） | 其它设备的旧会话访问 → 401 |
| S-07 | 验证码一次性（Core） | 同一 code 第二次消费 → `CODE_INVALID` |
| S-08 | 验证码限次（Core） | 5 次错误 → `CODE_EXHAUSTED`，发码需重新请求 |
| S-09 | 密码重置（Core） | 需经验证渠道；成功后旧会话全部撤销 |
| S-10 | 登出撤销（Core） | 登出后原 cookie 访问 → `SESSION_REVOKED`/401 |
| S-11 | 管理员强制下线（Core） | 被撤销会话立即失效；审计含 operator+reason |
| S-12 | 身份链接冲突（Core） | 同 subject 已绑他人 → `LINK_CONFLICT`，不自动合并 |
| S-13 | 封禁生效（Core） | disabled 账号的所有会话立即失效 |
| S-14 | 审计完整（Core） | 登录成败/封禁/撤销均有 actor+reason+time，含掩码 IP，无明文口令 |
| S-15 | 删除请求（Core） | PII 掩码/删除；审计事件保留匿名引用 |
| S-16 | TOTP 绑定与登录（MFA） | 未通过 2FA 不发会话；通过后发会话 |
| S-17 | 备份码（MFA） | 备份码一次性；TOTP 丢失可用备份码登录 |
| S-18 | OIDC 回调（Federation） | `state` 校验防 CSRF；按 subject 绑定；首次登录创建或显式链接 |
| S-19 | 多产品单点（MultiProduct） | 服务端按 scope 校验；不得跨域名共享裸 cookie |
| S-20 | 并发与幂等（Core） | 并发消费验证码恰 1 次成功；重复登出/撤销零副作用 |

## 5. 判定规则

1. 声明范围内 MUST 全过 + D-1~D-5 全过 → "ASP 符合（等级 X）"；
2. 任一 MUST 或 D 判据未过 → 不符合；D 判据不得降级豁免；
3. SHOULD 未过 → 记录偏差与风险；
4. 判定必须可复现（测试命令/期望/实际输出/时间戳）。

## 6. 反模式（出现即判定不符合）

- 用 JWT 裸存当"不可撤销会话"；把邮箱/手机直接当 User 主键；
- 登录错误区分"用户不存在"；把验证码做成"永不过期/可复用"；
- 密码重置不撤销其它会话；前端隐藏按钮代替服务端校验；
- 凭据/密钥进仓库或日志；审计丢登录失败事件；
- 认证层直接判"是否是会员"（权益判权必须在 MSP 的 Entitlement）。
