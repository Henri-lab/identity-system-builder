## 架构

### L-001 身份与凭据必须分离：users 表不存登录标识
- 日期：2026-10-14｜来源：设计推理（对齐 Auth0 identities / Keycloak federated identity）｜分支：任意
- 结论：邮箱/手机是"登录标识"，密码是"凭据"，都可能变、可能多份；塞进 users 表 + 唯一约束，多登录方式（邮箱+微信+手机）与换绑邮箱都无解。
- 为什么＋落地：拆成 `users`（主体）+ `user_identities(provider, provider_subject)` + `password_credentials`。已落 ASP A-1 + data-model.md。

### L-002 防枚举靠"统一响应 + 恒定耗时"，不是靠文案
- 日期：2026-10-14｜来源：设计推理（OWASP Authentication Cheat Sheet）｜分支：任意
- 结论：登录返回"该邮箱未注册"等于把用户库变成查询接口；正确做法是"用户不存在"与"密码错误"走同一条响应路径、同一耗时（包括先算一次假哈希）。
- 为什么＋落地：错误码统一 `INVALID_CREDENTIALS` + 恒定时间比较 + 限速锁定。已落 A-5 / S-02/04。

### L-003 会话要"可撤销 + 只存哈希"；JWT 裸存不是会话
- 日期：2026-10-14｜来源：设计推理（OWASP Session Management）｜分支：任意
- 结论：JWT 无状态 = 发出去就收不回，封禁/改密后仍可访问；会话必须服务端存哈希、能撤销、登录后轮换标识。
- 为什么＋落地：默认 server_cookie + sessions(token_hash, revoked_at)；JWT 只在多客户端场景作为短周期访问令牌评估。已落 A-3/4 + S-03/05/06/10。

### L-004 密码重置必须"经验证渠道"且撤销其它会话
- 日期：2026-10-14｜来源：设计推理（OWASP Forgot Password）｜分支：任意
- 结论：重置链接/验证码是临时的"身份凭证"；不验证渠道就被劫持，重置后不撤会话等于旧会话继续偷看。
- 为什么＋落地：验证码一次性、绑定 purpose、短 TTL、限次；重置成功后撤销全部其它会话。已落 A-6/7 + S-07/08/09。

### L-005 认证层只发 principal，不判"是不是会员"
- 日期：2026-10-14｜来源：设计推理（authN vs authZ；与 MSP INV-3 对齐）｜分支：任意
- 结论：登录成功 ≠ 有访问权 ≠ 是会员；三件事分属认证、授权、权益三层。认证层代判会员，一旦退款/到期语义变化就要改认证代码。
- 为什么＋落地：认证层产物只有 principal；权益判权在 MSP Entitlement；RBAC 是 P3 的独立权限引擎。已落 A-8 + conformance 反模式。
